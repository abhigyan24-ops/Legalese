# Data Model

## Overview

Rights Quest uses Firebase Firestore with three main collections. All users are anonymous (Firebase Anonymous Auth) — no personally identifiable information is collected anywhere in the system.

## Collections

### 1. users/{userId}

**Purpose:** Private user profile data, progress tracking, and game state.

**Document ID:** Firebase Auth uid (anonymous user identifier)

**Fields:**

| Field | Type | Description |
|-------|------|-------------|
| `avatar` | string | Parametric avatar identifier (e.g., "boy-short-red-medium") |
| `nickname` | string | Auto-generated nickname (e.g., "BraveTiger42") |
| `ageTier` | string | User's age bracket: "8-11" or "12-16" |
| `language` | string | User's selected language: "en", "hi", or "kn" |
| `xp` | number | Total experience points earned |
| `badges` | array | Array of badge objects: `{storyId, badgeName, badgeIcon, earnedAt}` |
| `completedStories` | array | Array of completed story IDs (strings) |
| `quizScores` | map | `{ [storyId]: { correct: number, total: number, completedAt: string } }` |

**Security Rules:**
- **Read:** User can only read their OWN document (`request.auth.uid == userId`)
- **Write:** User can only write their OWN document (`request.auth.uid == userId`)
- **Rationale:** Prevents cross-user profile browsing and data leakage

**Example Document:**
```json
{
  "avatar": "boy-spiky-blue-medium",
  "nickname": "BraveTiger42",
  "ageTier": "12-16",
  "language": "en",
  "xp": 350,
  "badges": [
    {
      "storyId": "education",
      "badgeName": "Education Champion",
      "badgeIcon": "🎓",
      "earnedAt": "2026-08-14T10:30:00Z"
    }
  ],
  "completedStories": ["education", "healthcare"],
  "quizScores": {
    "right-to-education": {
      "correct": 2,
      "total": 2,
      "completedAt": "2026-08-14T10:32:00Z"
    }
  }
}
```

### 2. leaderboard/{userId}

**Purpose:** Public scoreboard showing aggregate user stats (no private data).

**Document ID:** Firebase Auth uid (same as users collection)

**Fields:**

| Field | Type | Description |
|-------|------|-------------|
| `nickname` | string | User's nickname (copied from users doc) |
| `avatar` | string | User's avatar identifier (copied from users doc) |
| `xp` | number | Total XP (must match or be less than users/{uid}.xp) |
| `badgeCount` | number | Total number of badges earned |

**Security Rules:**
- **Read:** Public (anyone can read, including unauthenticated users)
- **Write:** User can write their OWN entry (`request.auth.uid == userId`) BUT `xp` value must not exceed the actual XP in `users/{uid}.xp`
- **Rationale:** Anti-cheat without Cloud Functions. The security rule validates writes by reading the source-of-truth users document. Client can update its own leaderboard entry but cannot fake a higher score. This replaces a Cloud-Function-based sync (which would require the paid Blaze plan).

**Example Document:**
```json
{
  "nickname": "BraveTiger42",
  "avatar": "boy-spiky-blue-medium",
  "xp": 350,
  "badgeCount": 2
}
```

**Indexes:**
- Composite index on `xp` (descending) for leaderboard queries

### 3. community_posts/{postId}

**Purpose:** Public reflection wall where users post short thoughts after completing stories.

**Document ID:** Auto-generated by Firestore

**Fields:**

| Field | Type | Description |
|-------|------|-------------|
| `storyId` | string | ID of the story this post is about (e.g., "education") |
| `text` | string | Post content (max 280 characters) |
| `authorId` | string | Firebase Auth uid of the post author |
| `createdAt` | timestamp | Server timestamp when post was created |

**Security Rules:**
- **Read:** Public (anyone can read)
- **Create:** User must be authenticated, set `authorId` to their own uid, text must be ≤280 chars, text must pass blocklist check
- **Update:** Never allowed (posts are immutable after creation)
- **Delete:** User can delete ONLY their own posts (`request.auth.uid == resource.data.authorId`)
- **Rationale:** Public wall (not 1:1 messaging) with content moderation via blocklist and immutability to prevent abuse

**Example Document:**
```json
{
  "storyId": "education",
  "text": "I learned that every child has the right to free education until age 14!",
  "authorId": "abc123def456",
  "createdAt": {
    "_seconds": 1723636200,
    "_nanoseconds": 0
  }
}
```

**Indexes:**
- Composite index on `storyId` (ascending) + `createdAt` (descending) for per-story post queries

## Security Principles

1. **No PII Collection:** No real names, emails, phone numbers, or addresses are stored anywhere
2. **Anonymous Auth Only:** All users are anonymous Firebase Auth sessions (uid only)
3. **DPDP Act 2023 Boundary:** By strictly eschewing the collection, storage, and processing of any Personally Identifiable Information (PII), Rights Quest architecturally avoids triggering India's Digital Personal Data Protection (DPDP) Act 2023 parental-consent framework.
4. **Private-by-Default:** Users can only access their own profile data
5. **Anti-Cheat Without Cloud Functions:** Leaderboard validation happens in security rules (Spark plan compatible)
6. **Immutable Posts:** Community posts cannot be edited after creation (reduces moderation burden)
7. **Blocklist Enforcement:** Server-side blocklist check in security rules (not just client-side)
8. **Deny-by-Default:** Any collection not explicitly listed is denied read/write access

## Firebase Plan Compliance

This data model is designed to work entirely on Firebase's **free Spark plan**:

- ✅ Firestore Database (free tier: 50K reads, 20K writes, 20K deletes per day)
- ✅ Anonymous Authentication (unlimited free)
- ✅ Firebase Hosting (10GB storage, 360MB/day transfer free)
- ❌ No Cloud Functions (would require paid Blaze plan)
- ❌ No Cloud Storage (not needed - parametric avatars only)
- ❌ No credit card required

**Expected Daily Usage (100 active users):**
- Reads: ~5K (leaderboard views, post feeds)
- Writes: ~500 (story completions, posts)
- Well within Spark plan limits

## Data Flow Examples

### Onboarding Flow
1. User completes onboarding screens (avatar, nickname, age, language)
2. `initAnonymousSession()` creates Firebase Anonymous Auth session
3. Create `users/{uid}` document with profile data
4. Navigate to Rights Map

### Story Completion Flow
1. User completes story, earns XP and badge
2. Update `users/{uid}`: increment `xp`, append to `badges`, append to `completedStories`
3. Update `leaderboard/{uid}`: set `xp`, `badgeCount`, `nickname`, `avatar`
4. Security rule validates that `leaderboard.xp` ≤ `users.xp`

### Community Post Flow
1. User completes story, clicks "Share reflection"
2. Client runs client-side blocklist check
3. Create `community_posts/{postId}` document
4. Security rule validates: auth, authorId match, text length ≤280, passes server-side blocklist
5. Post appears in public feed immediately

## Migration Notes

If the data model needs to change in the future:

- **Adding Fields:** Safe to add new optional fields (won't break existing docs)
- **Renaming Fields:** Requires data migration script + security rule updates
- **Adding Collections:** Remember to add explicit security rules (deny-by-default catches new collections)
- **Changing Security Rules:** Test in emulator first, deploy rules separately from app code
